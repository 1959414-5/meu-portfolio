ERP Industrial 3D com IA

Um painel industrial em 3D no qual o gestor conversa com os dados da fábrica: uma API Node lê o banco MySQL e um assistente de IA responde em português, consulta o banco por ferramentas seguras e leva a câmera até a máquina, o lote ou o vendedor citado.

01 · Visão geral

O problema e a proposta

Painéis de BI mostram números, mas raramente dizem onde está o problema e o que fazer a respeito. O projeto junta contexto espacial, dados de um banco relacional e uma conversa em linguagem natural, sem dar à IA acesso livre ao banco.

Objetivo

Construir uma aplicação completa, do banco ao navegador, que mostre a operação de uma metalúrgica em 3D e responda perguntas do gestor com dados reais da base.

  • Modelar um ERP industrial em MySQL, com vendas, estoque e produção.
  • Expor os dados por uma API Node/Express com consultas fixas.
  • Representar a fábrica em 3D e destacar máquinas, lotes e vendedores.
  • Integrar um LLM por function calling, com limites e alternativa offline.
  • Publicar tudo na nuvem sem custo.

Perguntas que o painel responde

  • Quais máquinas estão paradas ou com refugo alto?
  • Quais vendedores estão abaixo da meta?
  • Quais lotes de chapas estão abaixo do estoque mínimo e o que repor?
  • Qual é a tendência dos pedidos para os próximos períodos?
  • Como uma máquina se compara às demais?
Escopo e confidencialidade: este é um projeto independente de portfólio, com clientes, pedidos, máquinas, vendedores e estoque fictícios gerados por scripts SQL públicos. Não utiliza dados, marcas ou documentos de nenhuma empresa real.
02 · Arquitetura

Quatro camadas e uma rede de segurança

O navegador nunca fala direto com o banco nem recebe chaves: tudo passa pela API. Se a IA ficar indisponível, o painel continua respondendo com um motor local.

01

Banco de dados

MySQL 8 localmente e TiDB Cloud na nuvem. Scripts SQL idempotentes criam vendedores, chapas, máquinas, ordens e pedidos, com cenários variados para a demonstração.

02

API Node/Express

Rotas de dados, de saúde e de IA com mysql2, consultas SQL fixas, CORS configurável e limites de uso por IP e por dia.

03

Painel 3D

Vite, TypeScript e Three.js. Cena da fábrica, três abas (Produção, Estoque e Comercial), KPIs, gráficos e painéis arrastáveis.

04

Assistente de IA

LLM com function calling sobre 10 ferramentas. A resposta vem em português, com as ferramentas consultadas e ações como "Ver no 3D".

05

Alternativa offline

Motor local no navegador, com estatística e regras. Entra em ação sem API, sem chave, sem cota ou com erro do provedor.

06

Deploy gratuito

GitHub Pages com GitHub Actions para o painel, Render para a API e TiDB Cloud para o banco, todos em plano gratuito.

O schema erp_industrial_analytics cobre vendas, estoque e produção. Este projeto acrescentou a entidade de vendedores e scripts de carga que geram cenários realistas, em vez de um painel "todo verde".

Scripts idempotentes

Os scripts podem ser reexecutados sem duplicar dados. Os ajustes que alteram registros existentes rodam uma única vez, controlados pela tabela seed_log.

  • 01 cria vendedores, liga aos pedidos e cadastra as chapas.
  • 02 corrige o que as restrições CHECK barraram.
  • 03 expande para uma empresa de médio porte.
  • 04 cria os cenários variados de demonstração.

Cenários de demonstração

  • Máquinas: 10 operando, 2 com falha (refugo alto) e 3 paradas.
  • Vendedores: de 36% a 165% da meta.
  • Estoque: lotes cheios, equilibrados, abaixo do mínimo, críticos e sem estoque.
  • Cerca de 60 dias de apontamentos de produção.
  • Cumprimento do plano ajustado para um valor realista, perto de 94%.
Trecho real · status estimado da máquina (api/queries.js)
const horas = r.ultimo ? (ref - new Date(r.ultimo).getTime()) / 3.6e6 : Infinity;
let status = 'idle';                              // parada
if (prod > 0 && horas <= janela)
  status = refugo / (prod || 1) > 0.15 ? 'down'   // com falha: refugo acima de 15%
                                         : 'run';   // operando

O banco não tem sensores de chão de fábrica, então status e OEE são estimativas feitas a partir dos apontamentos, e a interface e o assistente deixam isso claro. A referência de tempo é o apontamento mais recente da base, não a data de hoje, e a janela é configurável.

Compatibilidade entre MySQL e TiDB

Dois detalhes funcionavam no MySQL local e falharam no TiDB Cloud. Os scripts foram ajustados para rodar nos dois e a correção foi reproduzida localmente antes de ser aplicada.

  • INTERVAL (expr) DAY deu erro 1582; INTERVAL ROUND(expr) DAY funciona nos dois.
  • Subtração com chaves BIGINT UNSIGNED deu erro 1690; a solução foi CAST(... AS SIGNED).

Modelo de dados

Chaves primárias e estrangeiras, restrições UNIQUE e CHECK, e duas views para consultas recorrentes. As chapas são produtos da categoria "Chapas", e a ocupação de cada lote é o saldo dividido pelo estoque máximo.

04 · API e segurança

Uma camada fina, com limites claros

A API em Node/Express entrega os dados do painel, protege as chaves e serve de ponte entre o modelo de IA e o banco.

01 / ROTAS

Endpoints

Rotas pequenas e com uma responsabilidade cada.

  • GET /api/data dados das três abas.
  • GET /api/health conexão com o banco.
  • GET /api/ping verificação de disponibilidade.
  • POST /api/ai/chat pergunta ao assistente.
  • GET /api/ai/models modelos e cota.
  • GET /api/ai/selftest diagnóstico dos provedores.
02 / SEGURANÇA

Camadas de proteção

A IA não recebe acesso livre ao banco nem às credenciais.

  • Chaves e senha apenas no servidor.
  • SQL fixo, parametrizado e somente leitura.
  • Defesa contra prompt injection: dados do banco são tratados como dados.
  • Limite de 20 perguntas por minuto por IP e teto diário de 300.
  • CORS restringível e HTML escapado na resposta.
  • Banco em nuvem com TLS.
03 / RESILIÊNCIA

Nada fica sem resposta

Cada falha tem um caminho alternativo.

  • Sem API: o painel usa um snapshot estático e, depois, dados de exemplo.
  • Sem chave, sem cota ou com erro: responde o motor local.
  • Modelo aposentado pelo provedor: a API descobre outro disponível.
  • Modelo fixado pelo usuário: o painel mostra o erro real, sem troca silenciosa.
05 · Assistente de IA

Function calling em vez de SQL gerado pelo modelo

O modelo não escreve SQL nem inventa números: ele escolhe, entre um conjunto fechado de ferramentas, qual chamar e com quais parâmetros. Cada ferramenta executa uma consulta fixa e somente leitura, e os cálculos pesados são feitos em código.

Como uma pergunta é respondida

  • O navegador envia a pergunta, o histórico curto e o contexto da tela.
  • A API valida o corpo e aplica os limites de uso.
  • O modelo escolhe uma ferramenta e a API executa a consulta fixa.
  • O resultado volta ao modelo, em um laço de até 6 voltas.
  • A resposta chega com texto, ações, sugestões e as ferramentas consultadas.

Recursos do assistente

  • Briefing automático ao abrir, com atalhos "Ver no 3D".
  • Respostas que levam a câmera até a máquina, o lote ou o vendedor.
  • Gráficos de barras e projeção linear com indicação de confiança (R²).
  • Seletor de modelos com status e cota. Nenhum provedor expõe o saldo em dinheiro, então a cota combina os limites devolvidos pelo provedor com o uso medido pelo servidor.
  • Sugestões de perguntas geradas pela própria IA.

07 · Problemas reais

O que deu errado e como foi resolvido

Cada caso segue a mesma ordem: sintoma, causa e correção.

Todas as máquinas apareciam paradas

Causa: o status comparava o último apontamento com a data de hoje, mas a base de demonstração era mais antiga.

Correção: a referência passou a ser o apontamento mais recente da base, com janela configurável.

Modelo de IA aposentado pelo provedor

Causa: o plano gratuito retirou o modelo configurado e as chamadas passaram a falhar.

Correção: a API lista os modelos disponíveis na chave e escolhe outro sozinha. Se o usuário fixa um modelo, o painel mostra o erro real.

Nome parcial respondido como inexistente

Causa: perguntar por um primeiro nome não casava com o cadastro completo, e o modelo concluía que não havia registro.

Correção: regra no prompt para resolver nomes pelas ferramentas de listagem antes de concluir, e sugestões com o nome completo.

Diferenças entre MySQL e TiDB Cloud

Causa: INTERVAL com expressão e subtração com chaves sem sinal funcionam no MySQL local, mas falharam no TiDB.

Correção: INTERVAL ROUND e CAST AS SIGNED, reproduzidos localmente antes de aplicar no banco da nuvem.

08 · Limites e evolução

O que o projeto não faz, e o que viria depois

Declarar os limites faz parte da engenharia: o projeto é uma demonstração, e as simplificações abaixo são conscientes.

Limitações conhecidas

  • Status e OEE são estimados a partir dos apontamentos, sem sensores. O OEE aqui é aprovado dividido por produzido.
  • "Produzido hoje" é o acumulado do período dos apontamentos, não o total do dia.
  • A projeção é uma regressão linear simples, sem sazonalidade.
  • A IA pode errar. Ferramentas fixas reduzem o risco, mas não o eliminam.
  • A demonstração é somente leitura e não tem login.
  • O plano gratuito da API tem partida a frio de cerca de 1 minuto.

Próximos passos

  • Autenticação com perfis de gestor e vendedor.
  • Dados em tempo real, a partir de sensores ou eventos das máquinas.
  • Testes automatizados das ferramentas, com perguntas-gabarito avaliadas a cada mudança de prompt.
  • Respostas em streaming.
  • Alertas proativos quando um indicador cruzar um limite.
  • Cache e índices no banco, e uma API sem partida a frio.
09 · Organização do repositório

Código, banco e documentação no mesmo lugar

O repositório reúne o painel, a API, os scripts SQL e os guias de IA e de deploy, para que outra pessoa consiga executar o projeto.

Principais diretórios

  • src/ painel 3D, interface, chat e motor local de IA.
  • api/ servidor Express, consultas SQL e ferramentas de IA.
  • db/ scripts SQL de carga, idempotentes.
  • docs/ guias do assistente de IA e do deploy, e imagens.
  • .github/workflows/ publicação automática no GitHub Pages.

Ambiente e publicação

  • Node.js 18 ou superior.
  • MySQL 8 localmente e TiDB Cloud Starter na nuvem.
  • Painel no GitHub Pages, API no Render, ambos em plano gratuito.
  • Segredos apenas em variáveis de ambiente, nunca no repositório.
